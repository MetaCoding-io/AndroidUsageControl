# S02: Listener foundation — UAT

**Milestone:** M007
**Written:** 2026-11-04T06:22:42.347Z

## UAT Type
- UAT mode: runtime-executable

## Preconditions
Debug APK installed on a device/emulator; notification listener access granted.

## Steps
1. `adb shell cmd notification post -t A tag1 "hello"`, then post again with the same tag and text "hello2". Expected: logcat NotificationCapture shows one key and updateCount=1.
2. `adb shell cmd notification cancel tag1`. Expected: the log shows reason APP_CANCEL; the DB has exactly one history row with updateCount=1 and removalReason set.
3. Start a media/FGS notification. Expected: it appears in live_notifications and not in history.
4. Force-stop the app, re-enable the listener, and reopen. Expected: icons load from filesDir/icons; the reconcile log shows the live table matching the active notifications.
5. Run `./gradlew connectedDebugAndroidTest` (com.usagecontrol.db). Expected: the migration and DAO tests pass.

## Edge cases
- Legacy v3 rows keep a NULL key and stay in stats.
- Ongoing rows are excluded from dismiss stats.

## Operational Readiness
- Health signal: NotificationCapture logs on every post/remove and a reconcile count line on connect.
- Failure signal: no logs after a test post, duplicate rows per key (the unique index would throw in the log), or a migration crash on startup.
- Recovery: re-grant listener access (triggers reconcile); the migration is non-destructive.
- Monitoring gaps: on-device only, no remote telemetry.
