# S05: Hardening: Hilt/KSP clean-build crash, Settings back arrow, dark mode check

**Milestone:** M007
**Slice:** S05

**Goal:** Eliminate the intermittent Hilt_UsageMonitorService NoClassDefFoundError on clean builds, give Settings a working back arrow, and make the window theme render dark in system dark mode.
**Demo:** Repeated clean builds launch without NoClassDefFoundError; Settings has a working back arrow; the app shows the dark theme correctly on the emulator in dark mode

## Must-Haves

- 5 consecutive `./gradlew clean :app:assembleDebug` runs each produce an APK containing Hilt_UsageMonitorService, and the app launches with no NoClassDefFoundError in logcat
- Root cause of the KSP/Hilt crash recorded in the T01 summary
- SettingsScreen has a navigationIcon (testTag settings_back) that pops back to Now; instrumented test SettingsBackTest passes
- values-night/themes.xml exists; with `cmd uimode night yes` the launch window and system bars render dark
- `./gradlew assembleDebug check :app:assembleDebugAndroidTest` exits 0

## Proof Level

- This slice proves: operational — real builds and emulator runtime (Medium_Phone_API_36.1); dark-mode visual check is screenshot-based

## Integration Closure

Settings route wired to navController.popBackStack in MainActivity; theme resources consumed by the launcher activity. Nothing else remains for M007 beyond pending on-device UAT.
