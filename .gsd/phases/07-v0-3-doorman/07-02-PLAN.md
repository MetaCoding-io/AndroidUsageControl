# S02: Listener foundation

**Milestone:** M007
**Slice:** S02

**Goal:** Rewrite the notification listener on a v4 Room schema: key-based upsert with update count and removal reason, a live table for ongoing/media/FGS notifications, a pure provisional-lane classifier, disk icon store and PendingIntent cache, and reconcile on listener reconnect, all without losing v3 data.
**Demo:** Post/update/remove a test notification yields one row with correct reason and update count; icons load after listener restart

## Must-Haves

- 1. Post, update, then remove a test notification gives exactly one history row with updateCount=1 and the correct removalReason (instrumented DAO test + adb device check).
- 2. Ongoing/media/FGS notifications go to the live table, not history or stats (stats SQL excludes isOngoing=1).
- 3. Icons are written to filesDir/icons/<pkg>/<hash>.png and load after a listener process restart.
- 4. After onListenerConnected, the live table matches getActiveNotifications().
- 5. MIGRATION_3_4 keeps v3 rows (MigrationTestHelper test against exported 3.json); no destructive fallback.
- 6. ProvisionalLaneClassifier JVM unit tests pass; :app:assembleDebug passes.

## Proof Level

- This slice proves: Integration: JVM unit tests for classifier, instrumented Room migration/DAO tests (device/emulator), adb device check for listener behaviour.

## Integration Closure

NotificationCaptureService writes v4 rows via the new DAO; IconStore/PendingIntentCache are Hilt singletons S03 (Now stream) consumes; NotificationRecord gains defaulted fields so existing screens compile unchanged.

## Verification

- Listener logs (tag NotificationCapture) per post/update/remove with key, updateCount, reason; reconcile logs counts added/removed.
