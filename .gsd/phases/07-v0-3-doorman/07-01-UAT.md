# S01: Toolchain and theme — UAT

**Milestone:** M007
**Written:** 2026-11-04T05:29:31.339Z

## UAT Type
- UAT mode: runtime-executable

## Preconditions
Debug APK built from `./gradlew assembleDebug`; Android device or emulator on API 29+ connected over adb.

## Steps
1. Run `./gradlew assembleDebug check`. Expected: exit 0.
2. Run `adb install -r app/build/outputs/apk/debug/app-debug.apk`, then `adb shell dumpsys package com.usagecontrol | grep -i label` or check the launcher. Expected: the label reads "Doorman".
3. Capture the launcher with `adb exec-out screencap -p > launcher.png`. Expected: an amber LED-dot icon on ink. With themed icons turned on, the monochrome icon renders.
4. Run `adb shell am start -n com.usagecontrol/.MainActivity`. Expected: the app launches without a crash and uses the Doorman dark theme.
5. Open the ComponentGallery previews in Android Studio. Expected: dark and light both render every component, and the lane colours are distinct.

## Edge cases
- Light system theme: the paper palette applies.
- BlockOverlayActivity uses DoormanTheme.

## Operational Readiness
Health signal: the build and check pass, LaneColorsTest and BundleCountLabelTest pass, and the launcher shows the Doorman label and icon. Failure signal: a build, lint or test failure, or a missing or blank icon on the device. Recovery: if KSP errors show up, run the module clean task; revert the catalog versions if the toolchain fails. Monitoring gaps: there are no screenshot tests, and the WorkManager initializer change hasn't been verified on a device.
