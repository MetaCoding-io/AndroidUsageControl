1. Create `MainViewModel.kt` in `app/src/main/java/com/usagecontrol/`:
   ```kotlin
   package com.usagecontrol

   import androidx.lifecycle.ViewModel
   import androidx.lifecycle.viewModelScope
   import com.usagecontrol.core.common.PermissionChecker
   import com.usagecontrol.core.common.onboarding.OnboardingRepository
   import dagger.hilt.android.lifecycle.HiltViewModel
   import kotlinx.coroutines.flow.MutableStateFlow
   import kotlinx.coroutines.flow.StateFlow
   import kotlinx.coroutines.flow.first
   import kotlinx.coroutines.launch
   import javax.inject.Inject

   @HiltViewModel
   class MainViewModel @Inject constructor(
       private val onboardingRepository: OnboardingRepository,
       private val permissionChecker: PermissionChecker,
   ) : ViewModel() {

       private val _startDestination = MutableStateFlow<String?>(null)
       val startDestination: StateFlow<String?> = _startDestination

       init {
           viewModelScope.launch {
               val onboardingComplete = onboardingRepository.isOnboardingComplete.first()
               if (onboardingComplete) {
                   _startDestination.value = "main"
               } else {
                   // ONBD-04: v0.1 upgrader auto-skip -- if all permissions already granted,
                   // user had v0.1 installed, skip onboarding entirely
                   if (permissionChecker.allPermissionsGranted()) {
                       onboardingRepository.setOnboardingComplete(true)
                       _startDestination.value = "main"
                   } else {
                       _startDestination.value = "onboarding"
                   }
               }
           }
       }

       /** Called when user completes or skips onboarding. Writes DataStore flag and returns. */
       fun markOnboardingComplete() {
           viewModelScope.launch {
               onboardingRepository.setOnboardingComplete(true)
           }
       }
   }
   ```

   Key behaviors:
   - `startDestination` is `null` until DataStore read completes (prevents NavHost flicker)
   - v0.1 upgrader path: DataStore key absent -> isOnboardingComplete returns false -> check permissions -> if all granted, write flag and route to main
   - `markOnboardingComplete()` is called by both "Skip" and normal completion -- identical code path per ONBD-03

5. Once startDestination is resolved, render Scaffold with NavHost:
   - The `showBottomBar` logic stays the same: `currentRoute in AppScreen.entries.map { it.route }` -- this already excludes onboarding routes since they are not in AppScreen enum.
   - NavHost `startDestination` = `startDestination!!`
   - Add nested onboarding graph:
     ```kotlin
     navigation(startDestination = "onboarding/start", route = "onboarding") {
         composable("onboarding/start") {
             OnboardingPlaceholderScreen(
                 onComplete = {
                     viewModel.markOnboardingComplete()
                     navController.navigate("main") {
                         popUpTo("onboarding") { inclusive = true }
                     }
                 }
             )
         }
     }
     ```
   - Wrap existing main tab routes in a nested main graph:
     ```kotlin
     navigation(startDestination = AppScreen.Notifications.route, route = "main") {
         composable(AppScreen.Notifications.route) { ... }
         composable(AppScreen.ScreenTime.route) { ... }
         composable(AppScreen.Controls.route) { ... }
         composable(AppScreen.Insights.route) { ... }
         composable(AppScreen.Settings.route) { ... }
         // Rule list and rule editor routes stay inside main graph
         composable("rules/{pillar}", ...) { ... }
         composable("rule-editor/{ruleId}/{pillar}", ...) { ... }
     }
     ```

   - `popUpTo("onboarding") { inclusive = true }` on completion/skip removes entire onboarding graph from back stack
   - When `startDestination = "main"` (returning user), onboarding is never in the back stack at all
   - Back press from Notifications tab exits the app -- never returns to onboarding

7. Keep `startMonitoringServices()` in `onCreate()`. The try/catch already handles permission-not-yet-granted gracefully. Services that fail to start will be retried after permissions are granted (Phase 2 concern).
